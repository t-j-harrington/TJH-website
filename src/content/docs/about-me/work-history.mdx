## <Image src={navroLogo} alt="Navro logo" width={48} style={logoStyle} />Navro <Badge text="November 2024 - September 2026" variant="tip" size="medium" />

I worked for Navro as their lead Technical Writer, reporting directly into the Chief Product Officer.

Navro is a fintech company that provides global payment curation. They have partnerships with a variety of banks and route a given payment through the best possible infrastructure.

Users of the Navro documentation could either be technical or less technical. As such, I implemented site-side filters that readers could use to adjust the information architecture to suit their needs.

### Summary

I worked as the sole technical writer at a scale-up, handling all aspects of documentation with other responsibilities too.

Working at a scale-up, a priority was transforming basic documentation into something mature enough for the enterprise contracts the company was signing.

While I worked at Navro, the strategy was to do more with less in order to extend runway and increase profitability as quickly as possible. This meant that I automated as many parts of the documentation as possible and used LLMs to aid in drafting content – so I had capacity to write the documentation that mattered most.

Alongside documentation, I also drafted release communications and implemented a changelog, alongside other achievements.

### Key achievements

- Managing the infrastructure of the documentation site (hosted through Redocly), including:
  - Maintaining a user list and permissions and applying role-based access control so this drove what readers saw.
  - Styling the site, designing icons, diagrams, CSS, and mermaid/plantUML diagrams.
  - Building scripts in the docs-as-code repo to automate updates based on the latest to an API (via hundreds of reusable MarkDoc snippets).
  - Creating client-side tools (no uploaded data) hosted on the docs site that readers could use to filter and create templated CSVs from complex JSON sources.
- Overhauling a bare bones suite of documentation into something robust that clients loved, including:
  - Building deep knowledge of the product then using that to create an intuitive information architecture (IA) for the docs.
  - 
- Developing relationships with stakeholders in Product, Engineering, Customer Success, and Commerical to ensure all documentation needs were captured.
- Building internal dashboards/webapps to ensure that less technical colleagues all had access to up-to-date data.

## <Image src={trueLayerLogo} alt="TrueLayer logo" width={48} style={logoStyle} />TrueLayer <Badge text="July 2022 - September 2024" variant="tip" size="medium" />

I worked for TrueLayer as a Senior Technical Writer.

TrueLayer is a fintech company that develops payments APIs and user interfaces based on the 'open banking' regulations in Europe.

The main users of the documentation were both internal and external people who were integrating with TrueLayer's APIs. This involved SMBs through to large corporate clients.

### Summary

I was the lead technical writer in a fintech startup of about 300 people with a $1 billion valuation.

In this position, I displayed autonomy and initiative, working in an ambiguous environment. I had to apply skills in information architecture, API documentation, and introducing organisational change.

I maintained the entirety of TrueLayer's integration documentation and API reference, including procedures, landing pages, references, release notes and more. I also worked with developers, writing UX text and API specifications.

I mentored a junior technical writer and acted as the scrummaster of a small agile team.

### Key achievements

- Several refactors of the documentation IA as the number of pages grew over 3x.
  This addressed growing product complexity.
- Created new quickstart guides, integration checklists, and REST API client collections.
  This reduced time to live for clients, boosting revenue.
- Worked with staff engineers to develop an API specification monorepo.
  This automated publication, reducing overheads and keeping the reference up-to-date.
- Achieved 1st and 2nd place in the two annual hackathons I participated in.
  This required wide product knowledge and presentation skills.
- Improved the visuals of the docs site through HTML, CSS, and consistent Figma assets.
  This kept the site on-brand, and enabled more diagrams, flows, and HTML elements.
